# Foundation Handoff

> Read this file before starting any new implementation work.

## Current state

- The plugin lives at `wp-content/plugins/alborsa-platform`.
- The `Foundation`, `Editorial`, `Assets`, `MarketData`, `Brokers`, `FinancialTools`, and `SeoIntegration` modules are wired. Editorial registers the public `alb_analysis` and `alb_guide` post types with the approved `/tahleel/` and `/taleem/` rewrite bases. Assets registers `alb_asset` without a generic archive.
- Eight taxonomies are registered with admin and core REST support: `alb_topic`, `alb_guide_level`, `alb_guide_track`, `alb_asset_type`, `alb_exchange`, `alb_sector`, `alb_broker_type`, and `alb_jurisdiction`. Their public taxonomy archives and rewrite rules remain disabled until URL contracts are approved.
- Asset singles use the approved `/aswaq/tadawul/{symbol}/` route for assets classified as `stock` on the `tadawul` exchange and `/forex/{pair}/` for assets classified as `forex`. Route queries enforce those classifications to prevent duplicate cross-route URLs; other asset classes keep WordPress query permalinks until their routes are approved.
- `AssetMeta` registers six public, single-value fields (`alb_canonical_symbol`, `alb_base_currency`, `alb_quote_currency`, `alb_isin`, `alb_official_website`, `alb_listing_status`) with sanitizers and per-post edit authorization. The structured `_alb_provider_mappings` field is protected and excluded from core REST responses.
- `AssetsModule` exposes read-only `GET /wp-json/alborsa/v1/assets` and `GET /wp-json/alborsa/v1/assets/{id}` routes. They return published assets only, cap collection requests at 100 items and page 1000, support search plus asset-type/exchange filters, omit protected provider mappings, and include published related content on detail responses.
- `wp alborsa assets import <file> [--dry-run]` imports bounded UTF-8 CSV files through `AssetUpsertService`. Each row requires an explicit Polylang language, title, canonical symbol, and existing language-matched asset-type term. Identity is `(language, canonical_symbol)`; missing optional columns are preserved on updates, new rows default to draft, and English rows cannot be published in the current phase.
- The provider-neutral Phase 3 runtime is implemented: `QuoteProviderInterface`, immutable `NormalizedQuote`, deterministic `MockQuoteProvider`, filtered provider discovery, bounded mapping batches, synchronization, targeted object caching, public reading, REST delivery, WP-CLI, and Site Health diagnostics. Decimal market values stay as normalized strings, timestamps require timezone-aware ISO-8601 input and are stored in UTC. No real provider or external request is configured while D-001 is open.
- The plugin-root `wpml-config.xml` makes the four implemented custom post types and eight taxonomies translatable in Polylang. Neutral asset, broker, and source fields use copy semantics; reviewer, last-reviewed date, and disclosure remain translation-specific.
- Content registration and permalink behavior are covered by isolated tests; a live WordPress integration pass with Polylang and Yoast remains required on Staging.
- The bounded database migration for Phase 2 relationships (`{$wpdb->prefix}alb_relationships`, e.g. `wp_alb_relationships` on a single-site installation) is implemented.
- Schema version `1` adds administrator capability `manage_alborsa_platform`.
- Schema version `2` creates the relationships table `{$wpdb->prefix}alb_relationships` idempotently using WordPress `dbDelta` with columns `id`, `from_object_id`, `from_object_type`, `to_object_id`, `to_object_type`, `relation_type`, `sort_order`, and `created_at` (a `datetime` column populated in UTC by `RelationshipRepository`), a unique key preventing duplicate relationships, and a reverse target lookup index. No foreign keys are added.
- Schema version `3` installs the shared `alb_content` capability map for the implemented product post types. Administrators and editors receive the ten generated primitive edit, publish, read-private, and delete capabilities; `manage_alborsa_platform` remains administrator-only.
- Schema version `4` creates `{$wpdb->prefix}alb_market_quotes` for the latest normalized snapshot per `(asset_id, provider_key)`. Decimal columns use `decimal(30,10)`, nullable unavailable values remain SQL `NULL`, and `QuoteRepository` performs prepared upserts and exact asset/provider reads without storing price history.
- `wp alborsa market sync --provider=<key>` scans published assets in bounded 100-asset pages, deduplicates provider symbols per batch, validates complete provider responses, persists the latest snapshots, and updates only affected `alborsa_platform_quotes` cache keys. It is intended for a real server cron; no WP-Cron visit trigger is registered.
- `QuoteReadService` and `GET /wp-json/alborsa/v1/assets/{id}/quote` return public quote fields, attribution, UTC timestamps, declared delay, status, and a stale flag without returning protected provider keys or symbols. A provider failure recorded after a snapshot marks that last value stale instead of deleting it.
- `BrokersModule` registers `alb_broker`, the approved `/brokers/` archive and `/brokers/{slug}/` singles, plus `alb_broker_type` and `alb_jurisdiction` with public taxonomy archives disabled. Broker posts reuse the installed `alb_content` capability map.
- `BrokerMeta` provides structured public profile fields and protected license records. `BrokerAdminMetaBox` saves them with nonce and capability checks. A license reaches the public presenter only when it has verified status, regulator, license number, official source URL, and verification date; internal notes never leave the protected record.
- Public broker reading is available at `GET /wp-json/alborsa/v1/brokers`, `GET /wp-json/alborsa/v1/brokers/{id}`, and `GET /wp-json/alborsa/v1/brokers/compare?ids=1,2`. Comparisons require two or three unique published broker IDs.
- Moderated reviews use WordPress comments with `comment_type=alb_broker_review` and prefixed protected comment meta. Only approved, non-rejected reviews contribute to the public list and average. Public submission and verified-review badges remain disabled while D-003 and D-013 are open; editorial scores remain null with `methodology_pending` while D-004 is open.
- `FinancialToolsModule` exposes a public catalog and stateless calculation route. Profit/loss, position size, pip value, and monthly compound-growth estimates are implemented as pure services with bounded string inputs, explicit assumptions, no persistence, and unit coverage. Zakat remains unavailable under D-006 and currency conversion remains unavailable under D-008.
- Editorial provenance metadata and a nonce/capability-protected editor box are implemented for posts, analyses, and guides. The explicit-language WP-CLI RSS importer accepts at most 50 safe public feed items, deduplicates by protected SHA-256 identity, and creates drafts only.
- `SeoIntegrationModule` extends Yoast's existing Article and WebPage graph pieces with supported source and review properties. It does not print a second graph or replace Yoast canonical/robots ownership.
- Broker review custom metadata participates in the WordPress personal-data exporter and eraser. A value-free, non-autoloaded 200-entry audit option records broker/editorial administrative mutations.
- The migration uses the current site table prefix and the existing network activation lifecycle, while real WordPress/MySQL table creation and network activation across multiple blogs remain unverified integration boundaries.
- Soft checks cover the seven existing WordPress plugins.
- Site Health reports migration, dependency, and market-provider state. `wp alborsa health` remains the Foundation migration/dependency command.
- Rewrite rules use a versioned Foundation service and are soft-flushed once, at late `init`, after activation or a rewrite contract version change.
- Isolated unit tests verify schema SQL definition and migration lifecycle orchestration.
- Quality checks run with `composer quality` from the plugin directory.
- A standalone custom theme lives at `wp-content/themes/alborsa`. On 2026-11-24 its visual layer began a clean rebuild from the approved Figma file: the new light/dark token foundation, WordPress editor palette, global header, theme switcher, accessible market ticker, mobile bottom navigation, global footer, and the complete 390px mobile design-system layer are implemented. `mobile-system.css` now applies the approved typography, spacing, cards, fields, lists, mobile data tables, calculators, broker controls, content states, overlays, and safe-area rules to the existing page templates. On phone widths the header is reduced to the official standalone brand mark and theme switcher while five primary destinations remain fixed above the device safe area; the footer keeps its compact risk notice, official brand mark and description row, three-column RTL link layout, and copyright strip. The official 123×44 Alborsa SVG variants remain reserved for full-logo placements; the dedicated 25×26 mark supplied by the user is now the only geometry used for compact brand icons and for the browser icon across frontend, login, and admin contexts, with a palette-matched dark variant. The previous Editorial Signal CSS files were removed; individual pages still require final comparison with their page-specific Figma frames.
- The theme reads only published WordPress content and the documented public asset identity fields. It does not read the quote table or provider mappings, manufacture prices, or activate broker CTAs. Calculator services now exist, but their theme forms remain an integration task.
- The news section now has a dedicated mixed post/analysis archive for both the configured posts page and `/akhabar/` page fallback, with bounded type/topic filtering, dated rows, pagination, a published-news sidebar, and a single-post reading layout with editorial provenance, related content, and functional sharing. Forecasts, saving, and notifications remain unavailable; the screenshot's mentioned-asset quote cards await an approved public article-to-asset read model and licensed data.

## Not implemented

- Remaining product modules, custom post types and taxonomies, custom editorial workflow statuses, remaining custom REST routes, or remaining feature tables (`alb_affiliate_links`, `alb_affiliate_clicks`).
- `RelationshipRepository` persists, deletes, and reads exact relationships with a 100-row read cap. `ContentAssetRelationshipService` validates `WP_Post` object roles and allows `mentions`/`analyzes` links from posts, analyses, and guides to assets; it has no admin UI or REST write route yet. D-002 approves Arabic on `/` and English under `/en/`; remaining product entity registration, write routes, caching, and administrative/data-service integration remain unimplemented.
- Real market providers, retry/backoff policy, user accounts, watchlists, or alerts. The complete provider-neutral quote runtime is implemented, but no external adapter is selected and no server cron entry is installed while D-001 remains open.
- Broker editorial scoring, public review intake, verified-review labels, and anti-spam integration remain blocked by D-003, D-004, and D-013. Affiliate CTAs remain unavailable until D-005 is approved and implemented.
- Live WordPress visual QA, real content population, menu/page assignment, and compatibility checks with the installed Polylang, Yoast, Breeze, and Object Cache Pro configuration remain staging tasks.
- The shared mobile system is applied across the homepage, archive, single, search, markets, tools, brokers, and state views. Final page-specific visual matching and desktop reconstruction still require their own Figma frames; do not use the previous theme styling as a fallback visual reference.
